# 토익 다의어 1단계: 후보 추리기 + 예문 시범 30개 (OpenCode)

사용자: "다의어나 해당 다의어에 대한 예문을 추가하면 좋을 것 같은데" "opencode에게 네가 직접 맡겨줘. 예문은 opencode가 쓰되 codex가 검토"
**packages/toeic.json은 읽기만 한다(다른 워커가 수정 중).** 결과는 `docs/senses/` 아래 새 파일로만. 코드 수정 금지, 커밋 금지.

## A. 후보 목록 → docs/senses/candidates.json
- toeic.json words: [표제어, ko, pos, ex, exKo]. ko에 뜻이 여러 개("주소; 다루다, 연설하다")인 단어 중, **토익에서 두 번째 뜻으로 자주 쓰이는** 단어 400개를 고른다(예: book 예약하다, address 다루다, issue 발행하다, charge 청구하다, account 설명/계정, figure 수치/생각하다, run 운영하다, cover 보도하다/보장하다, fill 채우다/주문 처리, reserve 예약하다/비축).
- 형식: `[{"index":번호,"en":"book","ko":"책; 예약하다","senses":[{"ko":"예약하다","pos":"동"}],"reason":"한 줄"}]`. senses에는 **기존 예문(ex)이 보여 주지 않는 뜻**만 넣는다(1~2개).
- 뜻이 비슷해 나눌 필요 없는 것(예: "결정하다, 정하다")은 제외.

## B. 예문 시범 30개 → docs/senses/draft-1.json
- A의 상위 30단어, senses 각 뜻마다 예문 1개: `[{"index","en","ko","pos","ex","exKo"}]`.
- 규칙: 토익 업무·생활 상황 문장, 12~20단어, 그 뜻이 문맥으로 분명할 것, 표제어(또는 활용형 booked/booking)가 문장에 그대로 들어갈 것. exKo는 해라체(~다). **틀에 단어만 바꿔 끼우기 금지**(문장마다 다른 구조·상황). 출판사 예문 복사 금지. 기존 ex와 같은 상황 반복 금지.

## 끝나면
두 파일 경로, A 개수, B 무작위 5개를 보고. 그 뒤 총괄이 기계 검사 + Codex 검토로 품질을 재고 나머지 진행 여부를 정한다.
