# UI 6차: 듣기 모드 (Codex UI 워커)

사용자 요청: "단어를 읽어주는 기능도 나중에 추가하면 좋을 것 같아." → "듣기모드 진행하자".
수정 가능: app.js, style.css, sw.js(앱 셸 캐시 버전 올리기), SPEC.md(화면 목록에 듣기 모드 짧게 추가). core.js·packages·test 수정 금지(코어 변경이 꼭 필요하면 하지 말고 보고).

## 기능
- 진입: Day 화면에 "듣기" 버튼 → `#/listen/<pkg>/<day>`. 오답노트에도 같은 버튼이 있으면 좋지만 선택.
- 재생 순서(단어마다): 영어 단어(en-US) → 한국어 뜻(ko-KR) → [예문 켜짐이면] 영어 예문(en-US) → 해석(ko-KR) → 짧은 쉼 → 다음 단어. 영어 단어 반복 횟수 1/2/3.
- 조작: 재생/일시정지, 이전/다음 단어, 속도(0.7/0.85/1.0/1.2), 예문 읽기 켬/끔, 반복 횟수, Day 끝나면 정지(반복 재생 토글은 선택).
- 화면: 현재 단어 크게(영어·뜻·예문), 진행 "n / 20", 진행 막대. 단어 목록에서 항목을 누르면 그 단어부터 재생.
- 기존 `speak()`(app.js:111)는 en-US 고정이고 cancel 후 말함 → 듣기용으로 lang·rate를 받고 onend로 다음 단계를 잇는 큐를 만들 것. 기존 카드 자동 발음 동작은 바뀌면 안 됨.
- 설정(속도·예문·반복)은 기기별 편의 설정이라 localStorage 별도 키(`vocab-master-listen`)에 try/catch로 저장. 학습 state/백업 형식은 건드리지 말 것.

## 견고성 (필수)
- 화면 이동(hashchange)·탭 숨김 해제 후 상태 꼬임 없이: 다른 화면으로 가면 즉시 `speechSynthesis.cancel()`하고 큐 정지. 늦게 도착한 onend가 다음 단어를 재생하지 않도록 세대(token) 확인.
- 일부 브라우저(Chrome)는 긴 재생 중 멈추거나 onend가 안 오는 문제가 있음 → 발화별 타임아웃 보조(예: 글자 수 기반 상한) 후 다음 단계로 진행.
- ko-KR 음성이 없으면 뜻은 건너뛰고 화면 안내 1회. 음성합성 미지원 브라우저면 버튼 비활성 + 안내.
- 접근성: 버튼 aria-label, 현재 단어 aria-live="polite", 키보드 스페이스=재생/정지.
- 화면이 꺼진 상태 재생은 보장하지 않음(브라우저 제약) — 화면에 한 줄 안내.

## 검증
