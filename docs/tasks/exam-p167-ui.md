# UI 15차: 문제 Part 1·6·7 화면 (UI 워커)

사용자: "파트 1을 포함해서 6, 7도 만들어 줘. 실제 토익 문제를 분석해서, 난이도와 유형 및 그림이 최대한 유사하도록 구현해줘."
데이터 형식: `docs/tasks/exam-p167-spec.md`(작성자 4명이 지금 쓰는 중). 실제 시험 분석: `docs/research/toeic-p1-p6-p7.md`.
기존 Part 2~5 화면(`js/exam.js`)의 흐름·스타일·기록 방식을 그대로 따르고, 새 구조는 최소로 만든다.

## 시작 전
공유 폴더 main 최신(커밋 891749f 이후)을 작업 폴더로 가져온다. 데이터 파일(packages/, questions/의 기존 파일) 수정 금지, 커밋 금지.

## 할 일
- **데이터 연결:** `questions/toeic-part1.json`(`{"version":1,"part":1,"questions":[...]}`), `toeic-part6.json`·`toeic-part7.json`(`{"version":1,"part":6|7,"sets":[...]}`). 파일이 없거나 비면 문제 홈에서 그 파트를 "준비 중"으로 보여 주고 에러 없이 넘어간다. sw.js의 QUESTION_FILES·검증 코드·테스트도 맞춘다.
- **임시 데이터:** 화면 확인용으로 `docs/pilot/part1/`의 시범 3문항(이미지는 `images/part1/`로 복사, image 경로 수정)으로 `questions/toeic-part1.json`을 만들고, Part 6 1지문·Part 7 단일 2세트(문자 1, 4문항 insertion 포함 1)·삼중 1세트(표 포함, crossRef 포함)를 직접 짧게 써서 임시 파일로 둔다. 임시 파일은 보고에 명시(총괄이 실데이터로 교체).
- **Part 1:** 사진(가로 꽉 차게, alt 포함)을 보여 주고 보기 4개를 시험처럼 **화면에 쓰지 않고 음성으로만** "(A) … (B) …" 순서로 읽는다. 답 버튼은 A~D. 답한 뒤 보기 문장·번역·해설 공개. 음성을 쓸 수 없으면 Part 2처럼 문장을 표시하는 대체 동작.
- **Part 6:** 지문(heading + 문단, 빈칸 `{n}`은 번호가 붙은 빈칸 표시) 아래 문항 4개. 지금 풀고 있는 빈칸을 지문에서 강조. 답한 뒤 빈칸에 정답을 채워 보여 주고 번역(paragraphsKo)·해설 공개. 문장 고르기 보기는 긴 문장이라 줄바꿈되는 보기 버튼.
- **Part 7:** 지문 종류별 표시 — 글(heading+body), 문자·채팅(시각·이름이 붙은 말풍선/줄), 표(table). 복수 지문은 문서 1·2·3을 위아래로 이어서 보여 주고 문서 사이를 구분. `[1]`~`[4]` 위치 표시, synonym 문항의 단어 위치를 찾기 쉽게(ref 문단 강조 정도). 답한 뒤 번역(passagesKo) 펼치기.
- **넓은 화면:** Part 6·7에서 화면 폭이 넓으면(약 900px 이상) 지문 왼쪽 / 문항 오른쪽 2단, 각각 따로 스크롤. 휴대폰은 지문 위·문항 아래 한 줄.
- 기록·오답·첫 시도 정답률은 기존 Part 2~5와 같은 방식으로 Part 1·6·7도 집계. 문제 홈 카드에 Part 1·6·7 추가(순서 1~7).
