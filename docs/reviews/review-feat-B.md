## 직접 수정

### 1. Part 1 유형 연습의 결과 이름 누락

Part 1은 `type` 대신 `photoType`을 사용한다. 필터는 이를 처리하지만 결과 화면과 단일 문항 채점 결과는 `q.type`만 읽어, ‘1인 사진’ 등의 이름이 빈 채 표시됐다. 채점 직후 해설 유형 이름도 같은 문제가 있었다.

`examQuestionType`으로 유형 취득을 통일하고 결과 집계·세션 결과·해설 이름에 적용했다. 실제 Part 1 문제를 유형 연습으로 풀어 ‘1인 사진’, `1 / 1`과 세션의 `single` 유형을 확인하는 회귀 검사를 추가했다. 저장된 정답 기록의 ID나 구조는 바꾸지 않았다.

### 2. Part 6 유형 연습에서 문맥이 불완전함

문장 고르기만 연습하면 해당 보기만 표시되지만 본문에는 네 빈칸이 모두 비어 있었다. 예를 들어 `p6-001`의 sentence 연습에서는 앞뒤의 `had confirmed`, `available`, `interview` 자리까지 빈칸이므로 해당 유형을 독립적으로 연습하기에 문맥이 불완전했다.

유형 연습에서는 선택하지 않은 빈칸만 정답으로 채워 본문 문맥을 제공한다. 선택한 유형의 빈칸은 계속 비워 두고 원래 문항 ID로만 채점한다. `readingPassage`에 명시적으로 유형을 넘기므로 일반 연습과 모의고사 본문은 기존처럼 모든 빈칸을 유지한다. 실제 Part 6 지문으로 비대상 세 칸 채움·대상 한 칸 유지와 일반 모의 본문의 네 빈칸 유지를 검사했다.

### 3. 유형 필터 변경 후 키보드 포커스 상실

새 select의 change 처리에서 `render()`가 화면을 교체하므로 선택 중이던 요소가 제거된다. 변경 후 같은 Part의 새 select에 포커스를 복원하도록 수정했다. 실제 앱의 change 처리기를 실행해 필터 값 변경과 포커스 복원을 확인했다.

### 4. 유형으로 제한한 LC의 완료 안내 문구

Part 3·4 유형 연습은 선택 유형의 질문만 재생하지만 완료 안내는 ‘세 문항의 답을 고르세요’로 고정돼 있었다. 필터가 있으면 ‘연습 중인 문항의 답을 고르세요’로 표시한다. 한 문항만 대상인 LC에서 대본과 해당 질문만 재생되는지, 완료 안내가 맞는지 검사했다.

## 검증

`node --check`로 core/app/exam/mock의 구문을 검사했고, 수정 diff의 공백 오류 검사도 통과했다. 새 JS 파일은 테스트 파일뿐이므로 앱 shell 등록 변경은 필요 없다. `CACHE_VERSION`은 유지했다.

초기 독일어 두 테스트 실패는 Windows 체크아웃의 CRLF가 원시 바이트 SHA-256을 바꾼 결과였다. 여섯 독일어 JSON 모두 CRLF를 LF로 되돌린 값이 Git 원본과 정확히 같고, 그 원본의 해시가 manifest와 같음을 확인했다. Git 원본과 동일한 LF 파일로 재검사해 통과했으며 코퍼스나 manifest 내용은 수정·커밋하지 않았다. 같은 검사를 재현하려면 LF 체크아웃을 사용해야 한다.

## 남은 권장 사항

- 유형 필터를 선택한 파트 카드의 학습 통계는 해당 유형이 들어 있는 **세트 전체 문항**을 집계한다. 실제 연습·채점은 선택 유형만 처리한다. 통계도 유형으로 한정하거나 집계 범위를 문구로 구분하면 더 명확하다.
- 유형 연습 중 LC의 영문 direction은 원래 세 문항 번호 범위를 유지한다. 보이는 문항은 필터링되고 한국어 설명은 이를 알리지만, 영문 direction도 현재 대상 번호에 맞추면 좋다.
- 총괄의 병합 후 360/900/1280px 및 라이트·다크 확인과, 실제 기기에서의 음색·pitch 구분을 확인한다. 브라우저가 pitch를 적용하는 정도는 VM 검사로 판단할 수 없다.
