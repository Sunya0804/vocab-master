- 검토일: 2026-11-15.
- 기준: `docs/tasks/review-feat-BC.md`, `feat-common.md`, `feat-C.md`.
- 비교: `main...feat/c`. 기준 main은 `b70d9252dc61f9397ef1022d6cbcd2fff2ce1f41`, 원구현은 `092b3bced5c7c2bbbacfe5c35c2f308ce3fedfc9`.
- 작업: 현재 터미널에 제공된 Dochi 격리 worktree를 재사용하고 `feat/c`를 직접 체크아웃했다. 이전 작업의 미정리 파일은 별도 보존했다. 공유 소스 수정·통합·push는 하지 않았다.

## 수정한 사항

| 항목 | 재현 / 수정 전 | 수정 후 / 근거 |
|---|---|---|
| 한글 뜻 검색 오매칭 | `각자`와 `가다`를 가진 단어장에서 `가`를 검색하면 둘 다 나왔다. NFD로 분리한 `각`의 자모 앞부분이 `가`의 자모와 일치했다. | 라틴 결합 부호를 제거한 뒤 NFC로 재조합한다. 한글 음절을 유지하면서 움라우트·대소문자·ß 정규화는 그대로 동작한다. 회귀 테스트에서 `가다`만 반환한다. |
| 반복 검색 성능 | 입력할 때마다 29,161개 단어의 단어·뜻·예문·다른 뜻을 모두 재정규화했다. 동일 Node 환경에서 반복 검색 한 번에 약 115~150ms였다. | 단어 배열별·독일어 정규화 모드별 파생 문자열을 WeakMap에 보관한다. 단어 배열 교체·길이 변경 시 새로 만든다. 같은 검색을 반복하면 약 1~4ms다. 실제 앱의 기본 단어장은 불러온 뒤 행을 수정하지 않으며 가져오기·복원은 새 배열을 쓴다. |
| 받아쓰기 배경 음성 | 받아쓰기에서 발음 재생 후 `visibilitychange` 또는 `pagehide`가 발생해도 기존 핸들러는 듣기·연습문제·모의고사 음성만 중단했다. | 받아쓰기 세션일 때 두 이벤트에서 `cancelSpeech()`를 호출한다. 실제 등록된 이벤트 핸들러를 실행하는 회귀 테스트로 중단 호출을 확인했다. |
| 받아쓰기 결과 포커스 | 전부 맞힌 뒤 결과 보기로 넘어가면 입력창도 재도전 버튼도 없어 다음 포커스 대상이 없었다. | 이름과 `tabindex=-1`이 있는 결과 영역으로 포커스를 옮긴다. 오답 유무와 관계없이 결과를 읽고 다음 링크로 이동할 수 있다. |
| 검색 더 보기 포커스 | 결과 목록을 다시 그리면서 누른 버튼이 사라져 키보드 포커스가 유실될 수 있었다. | 새로 표시한 첫 결과 링크로 포커스를 옮긴다. 201개 결과 중 첫 100개 뒤 더 보기를 누르는 테스트에서 101번째 링크를 확인했다. |

성능 수치는 이 PC의 Node.js v24.18.0에서 기본 단어장 9개를 모두 읽고 Core 검색만 측정한 값이다. 검색어는 `h`, `ha`, `hau`, `haus`, `계약`, `example`을 사용했다. 수정 후 최초 인덱스 생성은 약 174ms였으며 위 1~4ms는 생성 후 검색이다. DOM 렌더링·네트워크·휴대전화 성능 측정값으로 해석하지 않는다.

## 요구사항 대조

- 검색: 기본·가져온 단어장, 본문 예문과 다른 뜻의 예문, 단어장 이름·Day 표시와 이동 경로를 확인했다. 지연 로딩·실패 후 다시 불러오기 경로를 읽었고, 오프라인 캐시 검사는 네트워크 로더 호출 없이 캐시된 단어장만 읽는 테스트로 확인했다.
- 통계: 유효한 Day의 `studied` 기록과 실제 단어의 known ID를 집계한다. 삭제된 단어·없는 Day는 진행률에 포함하지 않는다. 연습문제는 문항별 최근 정오답을 사용하고, 모의고사는 회차별 최근 응시를 선택해 기존 환산 함수로 LC·RC·합계를 그린다. 미응시·빈 기록과 SVG/수치 표 출력을 확인했다.
- 받아쓰기: 정답을 채점 전에는 표시하지 않고 기존 `clozeCorrect`의 대소문자·독일어 키보드 규칙을 사용한다. 같은 답의 중복 제출, 오답노트 저장·재도전, 기존 퀴즈 최고점 보존을 확인했다.
- 독일어 발음: 공통 `speak`가 `speechVoice`로 독일어 음성을 고르고, 독일어 음성이 없는 목록에서는 안내가 한 번만 나오는 테스트가 통과했다. `ihr / Ihr`, `Deutsch / deutsch`의 앞 형태만 읽는 기존 공통 구현도 확인했다. 구분자가 아닌 TOEIC 표기 `lead (up/down) to`는 손대지 않았다.
- 저장·백업: 새 영속 상태 키는 추가하지 않았다. 받아쓰기 오답은 기존 `Core.recordAnswer`·`persist`·`Core.loadState`를 그대로 사용한다. 새 오답의 재로드와, 설정·문제·모의고사 필드가 없는 이전 학습 백업 복원 후 통계 출력을 테스트했다. 예전 백업에 없는 모의고사 기록은 기존 복원 정책대로 유지된다.
- classic script 순서, 새 파일의 `index.html`/`sw.js` APP_SHELL 등록을 확인했다. `CACHE_VERSION`은 바꾸지 않았다.

## 남은 권장 사항

1. 최초 검색 인덱스 생성과 전체 단어장 로딩의 지연·메모리는 저사양 휴대전화에서 확인할 필요가 있다. 대규모 사용자 단어장까지 늘어나면 인덱스를 나눠 준비하거나 Worker에서 만드는 방식도 고려할 수 있다.
2. 통계의 학습한 Day는 기존 `progress[package:day].studied` 기준이다. 퀴즈 최고점만 있는 Day·주제 단위·받아쓰기 완료는 별도 Day 완료로 계산하지 않는다. 집계 기준을 화면에 짧게 설명하면 이해하기 쉽다.
3. 총괄의 병합 후 확인에서 360px·약 900px·1280px 및 라이트/다크, 실제 기기의 독일어 음성 초기 로딩·음성 부재 안내·백그라운드 중단을 확인할 것. 특히 모바일 SVG 축 글자 크기와 긴 단어장 이름의 줄바꿈은 실화면 확인이 남아 있다.

확인된 코드 결함을 미해결 상태로 남기지는 않았다. 위 권장 사항은 추가 기기·표현·규모 검증 범위다.
